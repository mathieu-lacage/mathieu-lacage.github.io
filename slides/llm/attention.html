Multi-Head Attention (2017)

A layer runs H heads side by side, here H = 4. Input x: n × d, with d = H · dh

One product computes Q, K and V: x · [WQ | WK | WV], each W is d × d

Head 1 only uses its column slice of each W: d × dh, as on the previous slide

Regroup the slices by head: head h owns Qh, Kh, Vh, n × dh; the same x feeds them all

Each head computes its own attention Ah = softmax(Qh KhT / √dh + M)

Zh = Ah · Vh, n × dh: Ah to the left, Vh above, as on the previous slide

Side by side, the Zh form Z, n × d

WO is d × d, cut into H row slices of dh rows

Head 1 adds Z1 · WO(1), n × d, to O

Head 2 adds Z2 · WO(2)

Head 3 adds Z3 · WO(3)

Head 4 adds Z4 · WO(4): O = Σh Zh · WO(h) = Z · WO, n × d


def multihead(X, M, Wq, Wk, Wv, Wo, H=4):
    """H heads side by side; d = H * dh"""
    n, d = X.shape
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    Qh = np.split(Q, H, axis=1)
    Kh = np.split(K, H, axis=1)
    Vh = np.split(V, H, axis=1)
    # head h owns Qh[h], Kh[h], Vh[h]: n x dh each
    A = [softmax(Qh[h] @ Kh[h].T / np.sqrt(d // H) + M) for h in range(H)]
    Zh = [A[h] @ Vh[h] for h in range(H)]
    Z = np.hstack(Zh)
    Wo_h = np.split(Wo, H, axis=0)
    O = np.zeros((n, d))
    for h in range(H):
        O += Zh[h] @ Wo_h[h]
    return O

MHA: The reference

Two plots, log-log: context n from 1K to 1M tokens, ×4 per tick

MHA: the compute of a prefill of n tokens, and the KV cache it leaves

×4 tokens: ×16 compute, slope 2, O(n²); ×4 memory, slope 1, O(n)

At 128K: 4.5 PFLOP for the prefill, 69 GB of KV cache, 512 KiB per token

Quality: MHA is the reference, every variant is graded against it

Cost model, the same on every « where it stands » slide (themes/tradeoffs.js): a 32-layer model, d = 4 096, 32 query heads of d_h = 128, bf16 (Llama-2-7B's shape). Compute: QKᵀ and AV only (projections left out), prefill of n tokens, causal: 2 · n²/2 · 32 heads · 256 · 32 layers. Memory: K and V of all layers at context n: 2 · 4 096 · 2 B · 32 layers = 512 KiB per token. On a log-log plot a power law is a straight line, its slope is the exponent: n² slope 2, n slope 1, a constant slope 0. Parallel lines differ by a constant factor. The later slides: the variants seen so far in slate, the new one in gold, MHA in blue. Quality: three grades from each paper's own ablations, not one benchmark.

Multi-Query Attention (2019)

Same layer, H = 4 query heads, but a single key / value head: nkv = 1

WQ is still d × d, but WK and WV are only d × dh: one slice each

Head 1 uses its slice of WQ, and the only slice of WK and WV

Regroup by key / value head: there is only one, so all 4 query heads share K and V

Each query head has its own attention: Ah = softmax(Qh KT …): one set of keys, 4 queries

Zh = Ah · V: the same values, mixed 4 different ways

From here on, nothing changes: the Zh form Z, n × d

WO is d × d, cut into H row slices

Head 1 adds Z1 · WO(1) to O

Head 2 adds Z2 · WO(2)

Head 3 adds Z3 · WO(3)

Head 4 adds Z4 · WO(4): O = Z · WO, n × d, as in multi-head attention

Less compute: only one K and V across all heads per layer

Smaller KV cache: only one entry across all heads per layer

Multi-query attention (MQA, Shazeer 2019, « One Write-Head is All You Need »): GQA with n_kv = 1. The KV cache shrinks by H (here 4, often 32 or more in real models), which is what decode is bound by. The cost is quality and training stability, hence GQA as the middle ground (Ainslie et al. 2023 convert MHA checkpoints to GQA). Used by PaLM, Falcon-7B, StarCoder.

MQA: Smaller KV cache, bad quality

So far: MHA, compute O(n²), memory O(n)

MQA: compute does not move, every head still scores every key

At 128K: same FLOPs, 32× less KV cache, and a bit of quality lost

Settings of the cost model per variant: MQA 1 KV head; SWA W = 4 096 on MHA (the window alone); local / global: 5 SWA layers of W = 1 024 per global layer, on MHA; GQA 8 KV heads; MLA d_c = 512 + 64, keys 192 wide; DSA top k = 2 048, indexer 32 heads × 128 (FP8 key); KDA one 128 × 128 state per head, chunks of 64. MQA saves no attention FLOPs: only the K / V projections shrink. What it saves is the cache, and the bytes read per decoded token, which is what decode is bound by. MQA quality: GQA paper (Ainslie et al. 2023), T5-XXL uptrained: MHA 47.2, MQA 46.6, GQA-8 47.1.

Sliding-Window Attention (2020)

The multi-query layer: H = 4 query heads, one key / value head. Input x: n × d

One product computes Q, K and V: x · [WQ | WK | WV]

Head 1 uses its slice of WQ, and the only slice of WK and WV

Regroup by key / value head: all 4 query heads share K and V

Each head's attention Ah, with the causal mask: query i reads every key j ≤ i

Sliding window, W = 2: query i reads only keys i − W < j ≤ i; the rest is masked

Zh = Ah · V: each row mixes at most W rows of V; older rows of K and V are never read

From here on, nothing changes: the Zh form Z, n × d

WO is d × d, cut into H row slices

Head 1 adds Z1 · WO(1) to O

Head 2 adds Z2 · WO(2)

Head 3 adds Z3 · WO(3)

Head 4 adds Z4 · WO(4): same layer, same weights, only the mask changed

Sliding-window attention (Longformer's local attention, Beltagy et al. 2020; Mistral 7B, 2023): M_ij = −∞ also when j ≤ i − W. Shown here on the MQA layer, but the window is independent of the number of KV heads (Mistral 7B: GQA, 8 KV heads, W = 4 096). Head 2 read the first token: out of the window, its weight moves to its neighbours (illustrative pattern, renormalized). That first token is often an attention sink (inference.html, data/trace-Qwen3-1.7B-sink.json): StreamingLLM (Xiao et al. 2023) keeps the first few tokens on top of the window for that reason. A model trained with full attention (Qwen3) cannot just be given a window: SWA is a training-time choice. « Does « capital » never see « Paris »? »: it does, through the layers. Each layer extends the reach by W − 1 positions: after L layers, L · (W − 1) + 1. Mistral 7B: 32 layers × 4 096 ≈ 131 K tokens. Reach is not recall: information diluted over many hops, hence the global layers of the « Local and global layers » slide. Cost: the scores drop from ≈ n² / 2 to n · W, but only if the kernel skips the masked tiles (FlashAttention skips blocks that are entirely masked); a plain masked softmax still computes all n² scores and throws most of them away.

SWA: A bounded KV cache

Decoding « The »: its K and V go into both caches

« city »: one more entry in each cache; the window cache is full, its 2 slots used

« of »: overwrite the oldest slot. « The » is out of the window, its K and V are dropped

« Paris » overwrites « city »: slot = position mod W, a ring buffer

« is »: the full cache holds 5 entries, the window cache still 2

« the »: same, the window slides one token

« capital »: the full cache holds 7 entries

« of »: the full cache grows with n, the window cache stays at W

Mistral 7B at a 32 K context: 4 GiB of KV cache per sequence, 0.5 GiB with W = 4 096

The rolling buffer cache of the Mistral 7B paper: position i is stored in slot i mod W. Memory, and the bytes read per decoded token, stop growing with the context: decode is memory bound (roofline, « Inference »), so this is where SWA pays. Mistral 7B: 32 layers × 8 KV heads × d_h = 128 × 2 (K, V) × 2 bytes (bf16) = 128 KiB per token; × 32 768 tokens = 4 GiB, × 4 096 = 0.5 GiB per sequence. With paged attention (« Inference »), the same idea frees the pages that slid out of the window.

SWA: constant memory use but terrible quality

So far: MHA and MQA, same compute, 32× apart in memory

SWA: both bend at n = W: O(n) compute, the cache stops growing

At 128K: 16× less compute, 32× less KV cache, recall lost

SWA: Local and global layers

Mistral 7B: every layer is a sliding window, W = 4 096

KV cache capped at W per layer: 12.5 % of full attention at 32 K

Gemma 2: alternate local and global layers, 1 : 1

Gemma 3: 5 local layers (W = 1 024) for each global one

gpt-oss: alternates global layers and W = 128 local layers

Qwen3-1.7B: global in all 28 layers, its KV cache grows with n

KV cache at a 32 K context relative to all-global layers, same context for every model for the comparison (Gemma 2 is trained at 8 K): Mistral 7B 4 096 / 32 768 = 12.5 %; Gemma 2 (4 096 + 32 768) / 2 = 56 %; Gemma 3 (5 × 1 024 + 32 768) / 6 = 19 %; gpt-oss (128 + 32 768) / 2 = 50 %. The band widths in the small masks are schematic. Later Mistral models dropped the window (Mistral 7B v0.2: sliding_window null): SWA in every layer is the exception today, interleaving is the norm. Qwen3-1.7B, local config.json: use_sliding_window false, sliding_window null.

SWA Local / global: the best of both worlds

So far: SWA in every layer, a bounded cache, recall lost

5 local layers (W = 1 024) per global one: O(n²) and O(n) again, 6× lower

At 128K: 5.6× less compute, 5.8× less KV cache, quality back to ≈ MHA

Gemma 3's pattern on the MHA layer of the cost model: per 6 layers, 5 local (W = 1 024) and 1 global. Past a few K tokens the global layer dominates: compute and cache tend to 1/6 of MHA, the slopes of full attention come back. The win is a constant factor, not a complexity class. Quality: Gemma reports little loss from the local layers; the global layer keeps long-range recall.

Linear Attention (2020)

One head. Input x: n × d, one row per token

Q, K, V as in attention: x · [WQ | WK | WV]. No softmax: no n × n scores

Instead, a state S, dk × dv, starts empty: S0 = 0

« Paris »: S1 = S0 + k1 v1T: write v1 at key k1

Query right away: z1 = q1T S1. « Paris » reads only what it just wrote

« is »: S2 = S1 + k2 v2T: just add, nothing fades, nothing is corrected

z2 = q2T S2: S2 holds « Paris » and « is », summed

« the »: S3 = S2 + k3 v3T

z3 = q3T S3: each token reads the state it just wrote, one row of Z

« capital »: S4. S only grows: every write piles on the previous ones

z4 = q4T S4: Z is complete

Decode keeps only S4: dk × dv numbers per head, whatever n

« Transformers are RNNs » (Katharopoulos et al., 2020): the softmax is replaced by a feature map, exp(q · k) → φ(q) · φ(k), so (Q Kᵀ) V = Q (Kᵀ V), computed token by token: S_t = S_{t−1} + k_t v_tᵀ, z_t = S_tᵀ q_t the KDA recurrence without the decay (α = 1) and without the delta rule (u_t = v_t). Same drawing and same numbers as « Kimi Delta Attention » (themes/kda.js), α and β left out. Left out: the feature map φ (elu + 1) and the normalization z_t / (q_tᵀ Σ k_j).

Linear attention state update

One token t: St = St−1 + kt vtT. dk = dv = 4

Write: kt vtT, an outer product: row i is vtT scaled by kt,i

Add it to St−1: nothing is erased, nothing fades

Linear attention's update, drawn as « KDA: State Update » but without its erase and forget factors (KDA: S_t = (I − β_t k_t k_tᵀ) Diag(α_t) S_{t−1} + β_t k_t v_tᵀ). Numbers: tokens 1–3 of the linear animation give S_{t−1}, token 4 is t; S_t is S_4 there.

Linear attention: cheap, terrible quality

So far: every variant keeps every past token, or the last W

Linear attention: compute O(n), memory O(1) from the first token

At 128K: 341× less compute, 2 048× less memory, the worst recall

Grouped-Query Attention (2023)

Same layer, H = 4 query heads, but only nkv = 2 key / value heads

WQ is still d × d, but WK and WV are only d × nkv dh: fewer weights, smaller K and V

Head 1 uses its slice of WQ, and slice 1 of WK and WV

Regroup by key / value head: heads 1 and 2 share K1, V1; heads 3 and 4 share K2, V2

Each query head has its own attention: A1 = softmax(Q1 K1T …), A2 = softmax(Q2 K1T …)

Z1 = A1 · V1 and Z2 = A2 · V1: the same values, mixed differently

From here on, nothing changes: the Zh form Z, n × d

WO is d × d, cut into H row slices

Head 1 adds Z1 · WO(1) to O

Head 2 adds Z2 · WO(2)

Head 3 adds Z3 · WO(3)

Head 4 adds Z4 · WO(4): O = Z · WO, n × d, as in multi-head attention

More compute and more KV cache: K and V per group per layer

More accurate than MQA, less costly than MHA

Grouped-query attention (GQA): n_q query heads share n_kv key / value heads, n_q / n_kv query heads per group. n_kv = n_q is multi-head attention, n_kv = 1 multi-query attention (MQA). Qwen3-1.7B: 16 query heads, 8 KV heads, the same 2 per group as here; Llama-2-7B is plain MHA. Why: K and V are what decoding keeps for every past token (the KV cache, in « Inference »); halving the KV heads halves the cache, at a small cost in quality.

GQA: less memory, with no loss of quality

So far: MQA shares K / V heads, SWA forgets old tokens, linear attention keeps a fixed state

GQA: still the same compute, a KV cache between the two

At 128K: 4× less KV cache than MHA, quality back to ≈ MHA

Multi-Latent Attention (2024)

The multi-head layer again: H = 4 heads. Input x: n × d

One product x · [WDKV | WQ]: a narrow latent c, n × dc, and Q

A copy of c starts a second product, with WUK | WUV above: short weights, dc × d

c · [WUK | WUV] = [K | V], laid out like x · WQ = Q

Head 1 uses its slice of WQ, WUK and WUV

Regroup Q by head: Qh moves into the column of head h

Then K and V: Kh, Vh rise next to Qh, own per head, as in multi-head attention

Each head's attention Ah = softmax(Qh KhT / √dh + M)

Zh = Ah · Vh

From here on, nothing changes: the Zh form Z, n × d

WO is d × d, cut into H row slices

Head 1 adds Z1 · WO(1) to O

Head 2 adds Z2 · WO(2)

Head 3 adds Z3 · WO(3)

Head 4 adds Z4 · WO(4). Decode caches only c: dc numbers per token, not 2 d

Multi-head latent attention (MLA, DeepSeek-V2, 2024; kept in DeepSeek-V3/R1, Kimi K2): W_K = W_DKV · W_UK and W_V = W_DKV · W_UV, through a latent of width d_c ≪ d. GQA / MQA shrink the cache with fewer copies (heads share K, V); MLA with fewer numbers: every head keeps its own K_h, V_h, but all are rebuilt from the same c, which is all the cache holds. DeepSeek-V3: d = 7 168, 128 heads of d_h = 128, d_c = 512. Per token per layer, K and V: MHA 2 · 128 · 128 = 32 768 numbers, GQA with 8 groups 2 048, MQA 256, MLA 512 + 64 = 576 (the 64: the RoPE key, below). DeepSeek-V2 reports MLA above MHA in quality (their ablation, appendix D). In the drawing, d = 8 units, d_h = 2, d_c = 4 (2 d_h; DeepSeek: 4 d_h). Left out of the drawing: - Absorption, at decode: q_h · (c W_UK)ᵀ = (q_h W_UKᵀ) · cᵀ, so W_UK moves onto the query and K is never built; all heads then read the same cache of c: at decode, MLA is MQA with keys of width d_c (FlashMLA). Likewise W_UV folds into W_O. - RoPE does not commute with W_UK (the rotation depends on the position): a small decoupled key k_R = RoPE(x · W_KR), d_R = 64, shared by all heads and cached next to c. - The query side is low-rank too in DeepSeek (c_Q, 1 536 wide): saves parameters, not cache.

MLA: less memory, no loss of quality

So far: the cache cut by sharing heads (MQA, GQA) or by a window (SWA)

MLA: a bit more compute, a KV cache between MQA and GQA

At 128K: 14× less KV cache than MHA, quality on par

MLA does not make the attention cheaper: every head still has its own K_h, V_h, keys 192 wide (128 + 64 RoPE) against 128, so the prefill core costs 320 / 256 = 1.25× MHA. It saves on the K / V projections (≈ 6.5 M against 33.5 M multiply-adds per token here), linear in n: with the projections counted, MLA is cheaper up to n ≈ 13 K. At decode, with W_UK absorbed, each head scores against c, 576 wide: ≈ 4× the FLOPs of MHA per cached token, for 14× fewer bytes read. Quality: DeepSeek-V2 reports MLA above MHA (one ablation); TransMLA (2025) proves MLA ≥ GQA at equal cache size. Graded ≈ MHA here.

DSA, aka Sparse MLA (2025)

The multi-latent layer again: H = 4 heads. Input x: n × d

One product x · [WDKV | WQ]: the latent c, n × dc, and Q

A copy of c starts a second product, with WUK | WUV above

c · [WUK | WUV] = [K | V]

Head 1 uses its slice of WQ, WUK and WUV

Regroup Q by head

Then K and V: as in MLA, every head has its own Kh, Vh

Each head computes its MLA attention, as before: Ah = softmax(Qh KhT / √dh + causal mask)

New: a lightning indexer, x · WI = [qI | kI]: small query heads, one small key per token

Its scores Its = Σj wtj · ReLU(qItj · kIs): one n × n map, shared by all heads

The top k = 2 of each row of I give a mask M: 0 for the kept keys, −∞ for the others

M masks every head: Ah = softmax(Qh KhT / √dh + M). « capital » reads « Paris », not « the »

Zh = Ah · Vh: each row mixes at most k rows of V

From here on, nothing changes: the Zh form Z, n × d

WO is d × d, cut into H row slices

Head 1 adds Z1 · WO(1) to O

Head 2 adds Z2 · WO(2)

Head 3 adds Z3 · WO(3)

Head 4 adds Z4 · WO(4). Decode scans every kI, but reads only k rows of c

DeepSeek sparse attention (DSA, DeepSeek-V3.2, 2025; GLM-5.x): MLA, plus a lightning indexer that picks, for every query, the k past tokens attention will read. Same weights for Q, K, V, same output: only the mask changes, as in SWA, but chosen by content, not by position. GLM-5.3 (config in mirage/demo/glm53_dsa): 64 heads, d_c = 512 + 64 (RoPE key), indexer of 32 heads × 128, one key of 128 per token (FP8), top k = 2 048. Cost at decode, per layer and token, 128 K context: dense MLA reads 128 K × 1 152 B ≈ 151 MB of cache; DSA reads all index keys (128 K × 129 B ≈ 16.9 MB) plus 2 048 rows of c (≈ 2.4 MB): ≈ 19 MB. The indexer is still O(n) per token, but with tiny keys, ReLU and no softmax. Left out of the drawing: - the kernel never computes the masked scores: per query, sparse_mla gathers the k selected rows of c; same result as the mask, cost in k, not n. - the indexer query comes from the query latent c_Q (W_IQ: 2 048 → 32 × 128), its key and its weights w from x; the index key has its own LayerNorm and RoPE. - GLM-5.3 IndexShare: « shared » layers reuse the top k of the previous « full » layer and run no indexer. - Kernels (megakernel deck): dsa_index_score → dsa_index_topk → sparse_mla → dsa_mla_merge. - Training (to check): the indexer is first trained to match the dense attention, then the model is trained sparse. The scores and the selection in the drawing are illustrative.

DSA: less compute, no loss of quality

So far: MLA, same O(n²) as MHA, 14× less KV cache

DSA: the indexer is still O(n²), but attention reads only k keys

At 128K: about 2× less compute, a cache slightly larger than MLA’s

DSA's indexer scores every past key (32 heads × 128, FP8, no softmax): O(n²) with a smaller constant. The cache holds c plus one index key per token: 1 280 B per token and layer, against 1 152 B for MLA. The FP8 indexer is cheaper per FLOP than this count suggests.

Kimi Delta Attention (2025)

One head. Input x: n × d, one row per token

Q, K, V as in attention: x · [WQ | WK | WV]

Two more: a decay α ∈ (0, 1) per key channel, a write strength β per token

A state S, dk × dv, starts empty: S0 = 0

« Paris »: S1 = α1 · S0 + k1 u1T, u1 = β1 v1: S0 is empty, nothing to correct

Query right away: z1 = q1T S1. « Paris » reads only what it just wrote

« is »: S1 fades, row i × α2,i; u2 = β2 (v2 − what S already stores for k2)

z2 = q2T S2: S2 holds « Paris » and « is », nothing later

« the »: S3 = α3 · S2 + k3 u3T

z3 = q3T S3: each token reads the state it just wrote, one row of Z

« capital »: S4. Each token updates S once, in order

z4 = q4T S4, a mix of the rows of S4, weighted by q4: Z is complete

Decode keeps only S4: dk × dv numbers per head, whatever n

Kimi Delta Attention (KDA, Moonshot, « Kimi Linear », 2025): a linear-attention layer, gated delta rule with a per-channel decay. One recurrence per head, S ∈ ℝ^(d_k × d_v): S_t = (I − β_t k_t k_tᵀ) Diag(α_t) S_{t−1} + β_t k_t v_tᵀ, z_t = S_tᵀ q_t the update of the drawing: decay by α_t, then add k_t u_tᵀ, u_t = β_t (v_t − k_tᵀ Diag(α_t) S_{t−1}), the part of v_t that S does not already return for k_t. Without the decay (α = 1) it is DeltaNet; with one α per head (a scalar) Gated DeltaNet; KDA gives every key channel its own α (« fine-grained gating »). Why the delta rule: plain linear attention only adds k vᵀ, so S fills up; here the write first removes what k_t already retrieved. What S replaces: the n × n scores and the KV cache. Prefill is not run token by token: the chunked form (64 tokens per chunk) turns the recurrence into matrix products inside a chunk and passes S between chunks (fla: chunk_kda; decode: fused_recurrent_kda). Left out of the drawing: - q, k, v go through a short causal depthwise conv (kernel 4) and SiLU; q, k are L2-normalized. - α and the output gate come from low-rank projections (d → 128 → H·d_k); β = sigmoid(x W_β), one per head. GLM-5.3-Flash: α = exp(−5 · sigmoid(…)), in (e^−5, 1). - No RoPE: the decay already tells positions apart. - Hybrid models: Kimi Linear 3 KDA layers for 1 MLA layer; GLM-5.3-Flash 3 KDA for 1 DSA (notes/glm53-option-a-a2a-kda-math.md). GLM-5.3-Flash: 64 heads, d_k = d_v = 128: S = 64 · 128 · 128 = 1 M numbers per layer (4 MB in fp32), the same at 1 K or 1 M tokens of context. Each z_t is read right after S_t is written (causal). One head drawn: every head has its own slices of the W and its own S_h; the Z_h go through a gated RMSNorm, are concatenated, then O = Z · W_O, as in attention. The numbers in the drawing are made up, but the recurrence is computed from them.

KDA State Update

Eq. 1 is linear in S: St = At St−1 + Bt, At and Bt made from token t alone. dk = dv = 4

Erase: (I − βt ktktT) removes a fraction βt of what S stores at kt.

Forget: Diag(αt) scales row i of S by αt,i. Every read shrinks, most along key channels 2 and 4

At St−1: the old state, decayed per key channel, with what it stored at kt partly erased

Write: token t

Eq. 1 read left to right, as written: E_t = I − β_t k_t k_tᵀ, A_t = E_t Diag(α_t), then A_t S_{t−1}, then + β_t k_t v_tᵀ. Each product A · B = C has A left of C and B above it, as in attention. The kernels never form A_t (d_k × d_k): they apply it right to left, Diag(α_t) as a row scaling, then (I − β_t k_t k_tᵀ) S′ = S′ − β_t k_t (k_tᵀ S′), one read and one outer product, O(d_k d_v). Regrouped: S_t = S′ + k_t u_tᵀ, u_t = β_t (v_t − S′ᵀ k_t), the form of the token-by-token animation. Numbers: tokens 1–3 of the animation give S_{t−1} (themes/kda.js), token 4 is t. S_t here equals S_4 there (checked in the script).

KDA: best compute, best memory, terrible quality

So far: linear attention, the cheapest, but the worst recall

KDA: the same O(n) and O(1) as linear attention, a little more compute

At 128K: 256× less compute, 2 048× less memory, recall above linear, below MHA

KDA 3:1 : great memory, best quality

So far: KDA alone, O(n) compute, a fixed state, but the worst recall

3 KDA layers per MLA layer: O(n²) and O(n) again, from the MLA layers

At 128K: 3.2× less compute, 56× less KV cache, quality above MHA

Kimi Linear's pattern (Moonshot, 2025; also GLM-5.3-Flash with DSA in place of MLA): per 4 layers, 3 KDA and 1 MLA. Past a few K tokens the MLA layer dominates: the cache tends to 1/4 of MLA's (4× less, 56× less than MHA), the compute to 1/4 of MLA's (3.2× less than MHA, MLA being 1.25× MHA). As with local / global layers, a constant factor, not a complexity class. Quality: in a matched run (1.4 T tokens), Kimi Linear beats full MLA, RULER at 128K 84.3 against 81.3; the MLA layer keeps exact recall, the KDA layers the cheap bulk of the work.

From linear attention to KDA

Every model reads its state the same way, $z_t = S_t^\top q_t$; they differ by how they write it

2020Linear attention$S_t = S_{t-1} + k_t v_t^\top$a d × d state, no n × n scores
2023RetNet$S_t = {\color{#f5c451}\gamma}\, S_{t-1} + k_t v_t^\top$forget: a fixed decay γ per head
2023Mamba, GLA$S_t = {\color{#f5c451}\mathrm{Diag}(\alpha_t)}\, S_{t-1} + k_t v_t^\top$forget what the input says: αt from xt
2024DeltaNet$S_t = S_{t-1} + \beta_t k_t ({\color{#f5c451}v_t - S_{t-1}^\top k_t})^\top$overwrite, don't add: write the error
2024Gated DeltaNet$S_t = {\color{#f5c451}\alpha_t} (I - \beta_t k_t k_t^\top) S_{t-1} + \beta_t k_t v_t^\top$both: decay and delta
2025KDA$S_t = (I - \beta_t k_t k_t^\top)\, {\color{#f5c451}\mathrm{Diag}(\alpha_t)}\, S_{t-1} + \beta_t k_t v_t^\top$a decay per key channel

Still a fixed-size state: recall needs a few full attention layers, hence the hybrids

The gold term is what each step adds. Ten years of attention

2017: multi-head attention, the reference for quality and for cost

2019: MQA shares one K / V head, the cache drops, so does quality

2020: sliding windows bound the cache and the compute, recall suffers

2020: linear attention, a fixed-size state: the cheapest, the worst recall

2023: GQA, a middle ground, gets quality back

2024: Jamba, 7 Mamba layers per attention layer: the first big hybrid

2024: MLA compresses K / V: smaller cache, quality on par

2024: local and global layers: windows, with quality back

2025: DSA, MLA reading only the top k keys: compute down

2025: KDA, linear attention that forgets and overwrites: recall still behind

2025: 3 KDA layers per MLA layer: cheap and good

Conclusion

Long context is costly

Attention is O(n²) in compute and O(n) in memory

MHA

Shrink the memory

Sharing or compressing K and V shrinks the KV cache

MQA · GQA · MLA

Shrink the compute

Windows, sparsity and recurrent states cut compute, at a cost in quality

SWA · DSA · KDA

Mix the layers

Hybrids of cheap and full layers: the best compromise

SWA 5:1 · KDA 3:1

Sharing: MQA, GQA. Compressing: MLA. Windows: SWA. Sparsity: DSA. Recurrent state: KDA. Hybrids: local / global layers (Gemma), KDA / MLA (Kimi Linear). Cheap layers do the bulk of the work, a few full layers keep exact recall: the full layers set the slopes (O(n²), O(n)), the cheap ones divide the constant.
