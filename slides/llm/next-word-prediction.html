  • is not intelligent

Linear Algebra Refresher

A vector is a list of numbers

A vector is a list of numbers, written as a column: shape (2, 1), 2 rows and 1 column

In 2-D it is an arrow: x₁ = 3 steps along the first axis …

… and x₂ = 2 steps along the second

A token is a vector too: d = 2048 numbers in Qwen3-1.7B. No arrow to draw, same rules

d is the vector size: the deck uses n for the number of tokens. The colour strip is how x is drawn on the Self-Attention slides.

Cosine similarity

The cosine similarity of two vectors is cos θ, θ the angle between them

Same direction: θ = 0°, cos θ = 1

At right angles: θ = 90°, cos θ = 0. Unrelated

Opposite: θ = 180°, cos θ = −1

B twice as long, same angle: cos θ does not move. Only the directions count

Defines “similarity” before any formula: only the angle counts, the lengths do not.

Cosine from coordinates

Two vectors A = (3, 1) and B = (2, 5), at angles a and b from the axis: θ = b − a

Divide each by its length: $\hat A$ and $\hat B$ land on the unit circle. Their coordinates are the cos and sin of their angles

Project $\hat B$ onto $\hat A$: the foot is at distance cos θ from the origin

cos θ = cos(b − a), expanded with a trigonometric identity

Replace $\cos a$ by $\frac{a_1}{\|A\|}$, $\sin a$ by $\frac{a_2}{\|A\|}$, and the same for b

Put it over one denominator: $\cos\theta = \frac{a_1 b_1 + a_2 b_2}{\|A\|\,\|B\|}$ = 0.65

Whiteboard construction: shrink A and B onto the unit circle, project B̂ onto Â, then cos(b − a) = cos a cos b + sin a sin b and substitute the coordinates. The numerator a₁b₁ + a₂b₂ comes back two slides later: it is the dot product.

Dot product: multiply, then add

Two vectors of the same size, here d = 4

Multiply the first entries: 2 × 1 = 2

then the second ones: 1 × 3 = 3

the third: −1 × 2 = −2. Opposite signs pull the sum down

the fourth: 3 × 1 = 3

Add the products: $a \cdot b = \sum_i a_i b_i = 6$

Two vectors in, one number out

Two vectors of the same size in, one number out.

Dot product and cosine

In 2-D, the numerator of cos θ is the dot product: $a_1 b_1 + a_2 b_2 = A \cdot B$

So $\cos\theta = \frac{A \cdot B}{\|A\|\,\|B\|}$: the dot product carries the angle and both lengths

Same direction: both at their largest

At right angles: both 0

Pointing away: both negative

Same angle, B twice as long: cos θ does not move, A · B doubles

Both of length 1: $\hat A \cdot \hat B = \cos\theta$. Cosine reads the angle; the dot product reads angle and lengths

Attention scores are raw dot products (scaled by √d_h): a long key can win with a mediocre angle.

Input: a text

Tokenize: cut the text into tokens

Embed: id 60704 selects row 60704 of WE

id 374 selects row 374

id 279 selects row 279

Transformer block 2: same shape, new values

similarity[3, 0] = row 3 of hL · row 0 of WU

similarity[2, 0] = row 2 of hL · row 0 of WU

Unembedding similarity is dot product, mostly because it's a measure of how far apart two vectors are in the d dimensional space. cosine similarity would work maybe but it too expensive to calculate (it's a dot product over normalized vectors so, you need to normalize and to normalize, you need to calculate squares, etc.)

The Transformer black box

A transformer block: two sub-blocks

Attention mixes tokens causally: it works along n

The first row only sees Paris: never the future.

row 2 mixes Paris and is

row 3 mixes Paris, is, and the

row 4 mixes Paris, is, the and capital

FFN transforms each row on its own: it works along d

Output row 1 depends only on row 1

Output row 2 depends only on row 2

Output row 3 depends only on row 3

Same processing for every row: rows never interact

The real magic happens in the Transformer and more specifically in the Attention sub-block of the transformer that is responsible for learning the cross-position relationships

Self-Attention, one Head

Each token is a vector x: everything the model knows about it so far

Build a question (q for query) from « of »: “is it a city?”

Build an answer (k for key) from every token: its “cityness”

q and k have high similarity (85 %) for Paris

Build a payload (v for value) from every token: what it offers

Each value is weighted by how well its key matched with the query, then summed

The result is added to « of »: it now carries “France”

Intuitively, each vector becomes a linear combination of relevant parts of previous relevant tokens 1. read relevent dimensions of each input vector to ask a question: "Is City ?" 2. read relevant dimensions of each input vector to answer a question: "City-ness" 3. Calculate attention weights a_i : for each input vector Q_i, how well does input input vector K_j (j<=i) answer the question ? "This is a city" 4. read relevant dimensions of each input vector: "Country of city" 5. Weight "Country of city" by "This is a a city" 6. write back "Country" dimensions Figure: Qwen3-1.7B, layer 21, head 13. Real: the x strips, the arc weights (sink « The » left out, others renormalized), the words under the values (top unembedded token of W_O v). Cartoon: the bright peaks on q, k and v. W_K -> K 3. Q_i . K_j -> z_i (Q.KT) 4. W_V -> V 5. z = a_i x V_i 6. O=W_O . z

Takeaways: layers 1-3 heavily read « capital »; layers 7-21 read « Paris ». - First, in layers 1-3, we observe that we are reading from all dimensions of the capital position. Presumably, Q=K=subject-of, and V=capital the next token is going to be a "country" - Second, we observe that we are consistently reading from a few specific dimensions in the paris position. Presumably, it means that paris is a city/capital (Q=K=cityness), and that we are reading its country dimensions (V=country of city) to build france from layer 7 up to 21.

Conclusion

  • An LLM calculates next-token probabilities
  • Probabilities are derived from dot product similarity
